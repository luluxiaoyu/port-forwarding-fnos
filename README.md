# 本地端口转发

飞牛 fnOS 桌面应用。客户端访问「NAS 入口」，NAS 将 TCP 或 UDP 流量「转发到」目标服务。例如，入口端口填 `5055`，服务填 `127.0.0.1:10276`，客户端就通过 NAS 的 `5055` 访问服务。

一条规则可监听全部 IPv4 和 IPv6 地址。转发目标可以填写服务的具体 IP 或主机名，本地回环预设为 `127.0.0.1`。TCP 和 UDP 规则可以使用同一个入口端口。升级前已有的规则按 TCP 加载，备注可留空。

在应用中心手动安装与设备架构匹配的 FPK，然后从飞牛桌面打开「本地端口转发」。管理界面需要飞牛统一网关，实时跟随宿主主题需要系统支持飞牛页面主题 SDK。新规则默认监听全部 IPv4 / IPv6，两个入口都转发到 `127.0.0.1` 上填写的服务端口。管理界面和 API 通过 Unix Socket 提供，启用的转发规则按各自配置监听 TCP 或 UDP 端口。

## 构建

需要 Node.js 22.12+、Go 1.26+ 和 tar。在项目根目录执行：

```sh
npm --prefix frontend ci
npm --prefix frontend run check
go test -race ./...
node scripts/build_fpk.mjs
```

`dist_fpk/` 下会生成 `_amd64.fpk`（x86）和 `_arm64.fpk`（ARM64）。两个包使用独立的 Go 二进制和 payload 校验值。GitHub Actions 在 PR、`main` 推送和手动触发时上传安装包。发布 `vX.Y.Z` 格式的稳定版 Release 时，工作流会将从该标签构建的安装包附加到 Release。

## 设备验收与排查

- 通过应用中心启动或停止服务。启用的规则会在服务重启后恢复，规则保存在应用配置目录的 `rules.json`，日志位于应用数据目录的 `server.log`。
- 安装后从同一 NAS 和另一台局域网设备分别验证监听行为。重启或升级后检查原有规则，切换飞牛桌面主题并确认窗口同步刷新。
- 管理 Socket 默认只授予应用用户权限，具备系统权限的飞牛网关仍可访问。若网关使用非特权工作进程，先确认实际的网关专用组以及应用用户的组成员关系，再将该组的数字 GID 写入应用配置目录下的 `gateway-gid` 并重启。此时 Socket 只对应用用户和指定组开放。验收时用普通飞牛账号检查管理 API 返回拒绝。
